### Docs
- **Simulation (MuJoCo)**: `_recompile_preserving_state` no longer documents `qfrc_applied` as "deliberately NOT carried here". It has carried that buffer since the grow path gained `_snapshot_joint_forces` and its restore, so the docstring said three things at once - that both applied-force buffers are snapshotted by name (true), that `xfrc_applied` is carried (true), and that `qfrc_applied` is deliberately not, followed by an instruction that "a joint-force API added later must add the carry with it" (false, and the carry was already there). Both force-buffer bullets now name the helper pair that performs the carry, the way `_SceneState`'s own docstring already does. A derived guard holds the prose to the code: the functions checked are those that call a `_snapshot_*` helper, and the buffers each carries are the `data.<buffer>` fields those helpers read, so no carried buffer can be documented as uncarried and a buffer added later is graded on arrival.
