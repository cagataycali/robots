### Fixed: `robot_mesh(action="stop", target=...)` over Device Connect reported a stop as successful as long as the device's `stop` RPC returned a reply, so a device whose allowlist refused the caller, or whose `stop_policy` could not halt a rollout, came back under `status="success"` with an audit row recording `ok=True`. The single target is now graded with the same rule the fleet-wide `emergency_stop` branch and the built-in mesh path already read: a device that reports it did not stop turns the result into an error naming the target and its answer, audits the verdict as a failure, and is logged at CRITICAL. A reply that reports no verdict either way is still not read as a refusal.
