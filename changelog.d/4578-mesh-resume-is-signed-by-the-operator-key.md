### Fixed: clearing an e-stop lockout needs the operator's signature, not a code every robot holds

The RPC `resume` action read `override_code` from the command body, so the code crossed `strands/<robot>/cmd` in plain text where every peer the ACL lets subscribe could read it, and every robot held the same code because each verifier recomputed the proof from it. Resume is now an Ed25519 assertion signed by the operator's key (`strands_robots.mesh.resume_authority`; create one with `python -m strands_robots.mesh.resume_authority keygen <key-file>`). Peers hold only the public half in `STRANDS_MESH_RESUME_PUBLIC_KEY`, so no robot can mint a resume. The assertion names the lockout epoch (the new `estop_id` on `strands/safety/estop`, `Mesh.lockout_epoch`) and its target peers, so a captured one cannot clear another robot or a later lockout, and its nonce is single use. `Mesh.resume(key)` signs and relays one; the RPC carries `{"action": "resume", "assertion": ...}`. A command that still carries `override_code` is refused and audited, and a peer with no verification key keeps its lockout. The dashboard signs with the key file named by `STRANDS_MESH_RESUME_SIGNING_KEY_FILE`, opened with the passphrase the operator types; a key file is written only under a passphrase of 16 characters from three character classes. `STRANDS_MESH_OVERRIDE_CODE` is no longer read (a start-up WARNING says so), `override_code()` and `resume_proof_key()` are removed, and a fleet upgrades all peers together.
