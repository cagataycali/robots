### Fixed: a mesh ACL `cert_common_names` entry is a non-empty string or the ACL is refused

`_validate_acl_shape` graded the container of a subject's `cert_common_names` and not its entries, while the sibling `interfaces` field grades both. A `null`, a number or a nested list therefore passed the validator and reached the Zenoh parser at `Mesh.start`, which refuses it as `invalid type: ..., expected a string` at a line and column of the wire JSON the operator never sees, naming neither the ACL file nor the subject. An empty string passed both: Zenoh accepts it, a common name is matched literally, and no certificate carries an empty one, so the subject matched no peer - the silent "match nothing" outage the validator exists to refuse - while `[""]` was truthy enough to pass the wildcard guard as a constraint. Each entry is now graded, and the refusal is path-prefixed like every other in this validator, naming the subject, the entry index and the type received. `[]` is unchanged and stays the wildcard guard's case. Pinned by `tests/mesh/test_acl_shape_validation.py`.
