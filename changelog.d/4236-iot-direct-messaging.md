### Added: every mesh peer is directly addressable over AWS IoT Core Direct Messaging

On the `iot` and `bridge` backends, `Mesh.send` now delivers a command to the one connected client it names as an [AWS IoT Core direct message](https://docs.aws.amazon.com/iot/latest/developerguide/direct-messaging.html), with confirmation (QoS 1 and the robot's PUBACK), and the robot replies the same way on the `responseTopic` it received, after checking that it is exactly `strands/<sender>/response/<self>/<turn>` for the validated sender. Neither side needs a subscription for it; a robot that is not connected answers `peer offline (iot 404)` in one round trip instead of after the caller's timeout (30 s by default). Measured in us-west-2: round trip p50 220 ms, offline verdict under 300 ms. `broadcast`, presence, state and safety stay publish/subscribe, and the `cmd` and `response/**` subscriptions stay, so an older peer is still heard. A 403 on the first direct attempt is logged once and that peer falls back to publish; `STRANDS_MESH_IOT_DIRECT=0` turns direct messaging off; `STRANDS_IOT_DIRECT_AUTH` selects the certificate (`x509`, default when the files exist) or IAM credentials (`sigv4`) for the HTTPS call.

The transport layer gains `DirectSender` and `DirectResult` next to `MeshTransport` (`IotMqttTransport` and `BridgeTransport` implement it, Zenoh is unchanged), the MQTT sample wrapper exposes `response_topic` and `correlation_data`, and an inbound direct message on this thing's `cmd` or `response/#` topic reaches its handlers even without a subscription.

Provisioning changed with it. `provision_robot` and `provision_operator` now generate the private key on the machine and have AWS sign a certificate from a CSR with `CN=<thing name>, O=strands-robots` (`CreateCertificateFromCsr`; `cryptography` when importable, else the `openssl` command); the key never leaves the robot. This is what the new robot grant `AllowDirectResponseToAnyOperator` needs, because an HTTPS call has no MQTT connection for `${iot:Connection.Thing.ThingName}` to resolve from and `${iot:Certificate.Subject.CommonName}` is the variable that works. A robot provisioned before this release keeps working over publish/subscribe and uses direct replies after `provision_robot` is re-run. The operator policy gains `AllowDirectCommandToAnyRobot` (`strands/*/cmd` only) and `OperatorAnnounceSelf` (its own presence and health, without which the broker dropped an operator Mesh session on its first presence publish). `_ensure_policy` publishes a changed document as the policy's new default version instead of leaving the account's copy at whatever revision first created it; doing so surfaced that the `OperatorShadow` statement carried a `Condition` on `iot:Connection.Thing.Attributes.*` which AWS IoT rejects as malformed, so that condition is gone (the `strands-` Thing-name prefix was the control that was ever enforced). `bootstrap_account` creates the IAM managed policy `strands-operator-direct` for SigV4 senders and `teardown_account` removes it. `strands-robots doctor` gains an `IoT Direct` row that sends this peer a confirmed direct message to itself and names the certificate CN on a 403. Docs: `learn/mesh/direct.md`.
