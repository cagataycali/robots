### Fixed:
- `strands-robots doctor` no longer passes a configuration the runtime refuses. Three rows were measured green while the same environment failed at first use: `lerobot` imported with a torchcodec that could not load (the first `LeRobotDataset` then printed the loader traceback and fell back to pyav), nothing said what `Robot(...).run()` would do about TLS on device-connect, and "zenoh available" printed while `Robot(mesh=True)` logged "Mesh did NOT start". The doctor is now a table of `(label, probe)` rows; the new `Torchcodec` row imports torchcodec's native ops and names the loader's reason with the ffmpeg or torch-ABI remedy that fits, the `Device Connect` row reports the posture `run()` would take through the runtime's own decision functions (skipping until this build exposes them), and the `Mesh` row runs the same auth-mode + ACL gate as `Mesh.start`, prints its "Pick one" text on refusal (now one shared constant), and reports the hub port owner, each `ZENOH_CONNECT` endpoint's reachability, and multicast scouting - without opening a session.
