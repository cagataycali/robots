### Fixed: `Gr00tPolicy` refuses a non-boolean `strict` or `strict_keys`. Both were stored as given and read by truthiness, so `strict_keys="false"` -- the spelling a JSON `policy_config` reaches for to opt out -- selected the strict posture and then reported it as `strict_keys=True: cannot resolve video keys by exact name` to a caller who had asked for the positional fallback, while `None` and `0` took the permissive branch while spelling neither. Each is now checked with the same domain as `lerobot_local`'s `strict_keys`, naming the parameter and the value it was given; `True`, `False` and NumPy booleans are stored as given.
