### Fixed: an `rtc_enabled=True` policy no longer hands its RTC to every other policy built from the same checkpoint in the same process. RTC is configured on the model - `_init_rtc` writes `config.rtc_config` and lerobot builds the module's `rtc_processor` from it - while the process model cache handed one module to every wrapper keyed the same way, so a later policy built with defaults auto-detected RTC it never asked for (`supports_rtc` True, re-query interval collapsed from the trained chunk to the RTC horizon) and an earlier one kept driving an RTC-enabled module through `select_action`, which lerobot asserts against. The caller's RTC request is now part of the cache key, so policies that asked for different RTC get one resident copy each and policies that asked for the same RTC still share one.
