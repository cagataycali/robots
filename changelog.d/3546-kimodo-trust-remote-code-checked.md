### Fixed: `KimodoConfig` refuses a non-boolean `trust_remote_code`. The field was declared `bool` and checked nowhere - `__post_init__` validated every numeric knob, `dtype`, `model_id` and `seed` around it - and the value reached `DiffusionPipeline.from_pretrained` as given, which reads it by truthiness. So a JSON `policy_config` spelling the opt-out as `"false"` (or `"no"`, `"off"`, `"0"`) had the checkpoint's own code executed for the caller who asked it not to. It is now checked with the same domain as every other posture flag, ahead of the other knobs and at the one site every route re-validates through; `None` on the policy keyword stays the not-supplied sentinel, and `True`, `False` and NumPy booleans are stored as given.
