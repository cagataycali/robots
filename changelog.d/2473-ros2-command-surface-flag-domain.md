### Fixed
- **hardware ROS 2 bridge**: check the flags that decide whether a robot exposes an inbound `joint_command` surface instead of reading them by truthiness. `ros2_bridge`, `ros2_commands` and either bridge class's `enable_commands` now go through the shared `boolean_flag_error` domain, so `"false"` / `"no"` / `"off"` / `"0"` from a deployment config are refused at construction rather than selecting the arm-driving posture they ask to close - and the RTPS DDS Security gate, which branches on the same flag, no longer answers a read-only request with the insecure opt-out that would open it.
