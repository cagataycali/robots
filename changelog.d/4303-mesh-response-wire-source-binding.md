### Fixed: a mesh RPC reply is attributed to the Zenoh session that sent it, not to the `responder_id` it claims

`Mesh._on_presence` records the TLS-bound wire session each peer announces itself from (first live session wins, a peer silent past `PEER_TIMEOUT` may return on a new one), and `Mesh._on_response` refuses a reply whose wire source is not that session, on broadcast turns too, with a `response_hijack_rejected` audit record. A broadcast turn takes one answer per verified session. `Mesh.emergency_stop` names roster peers that gave no acknowledgement as `peers_silent` in the safety envelope and the audit event. Any admitted peer could previously answer a fleet emergency stop in another robot's name and the operator saw a clean verdict for a robot that never stopped (f004).
