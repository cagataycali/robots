### Docs: pictures that come from the code, on almost every page

The docs site answers the first round of review. Code blocks are highlighted
again (keywords, strings, functions and numbers in the site's own colours); the
architecture page shows what each layer is for instead of a wall of line
counts; the robots catalog filters by real driver, simulated or both; and a
robot description containing a quote no longer breaks the page it is on.

Every simulation page (MuJoCo, Newton, mjlab, Isaac Sim) shows a short clip
recorded by running the page's own code block, with the still frame as its
poster; a hook records them and a test keeps every clip matched to the block
that made it. The Isaac Lab training page streams the five trained
rough-terrain policies from the Hub, with the success rate and reward read from
each repository's own files, never typed. The dashboard page shows the running
dashboard with a simulated SO-101 on the Fleet tab, in both colour schemes.

The drawings move: the one thing each drawing is about is lit, flows or
breathes, every drawing carries the STRANDS mark, and a reader who asked their
system for less motion gets a still picture. Seven new drawings join the ten:
the simulation backends, the Policy contract, the trainer lifecycle, recording,
the dashboard over the mesh, the three ROS 2 transports and the security
layers; twelve more pages open on one.
