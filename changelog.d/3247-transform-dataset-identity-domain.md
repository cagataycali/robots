### Fixed

- `TransformSpec.source_repo_id` / `output_repo_id` are held to a non-empty string by the shared transform preflight. They were the only spec fields with no value domain, and `source_repo_id` is written verbatim into every provenance record - the key answering which dataset a generated episode's trajectory came from - in a sidecar written only after every generated episode is already on disk. An identity `json.dumps` could not render therefore raised out of that write with the whole augmented dataset already written, and a dataset with no provenance file declares no synthetic episodes at all, so `synthetic_episode_indices()` returned an empty set for a fully generated dataset and a training filter read generated pixels as recorded. A blank identity was accepted too, writing a record that named nothing. `validate()` now refuses both before the first episode instead of at the sidecar write; no `owner/name` shape is imposed, since `output_root` is the load-bearing path.

  Pinned by `tests/transforms/test_spec_domains.py::TestDatasetIdentities` (the domain, table-driven over both ends) and `tests/transforms/test_round_trip.py::test_an_unrecordable_identity_is_refused_before_any_episode_is_written` (the end-to-end guarantee that no dataset reaches disk without the sidecar that marks it synthetic).
