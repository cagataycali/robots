### Added
- **docs guard (cosmos3)**: tie every embodiment enumeration on `docs/policies/cosmos3.md` and the README provider row to `EMBODIMENTS`, so adding a cosmos3 embodiment cannot leave the page documenting a smaller accepted set than `create_policy("cosmos3", embodiment=...)` takes. The page enumerated the set six times by hand (front matter, the `## Embodiments` table, the first example's `# droid | umi | ...` comment, the domain/raw-dim/bundled-stats table, the bundled-vs-unbundled count above it, and the README row) and nothing checked any of them - the provider-level guard grades providers, so an embodiment added to an existing provider was graded by nothing. The tables' per-embodiment facts are graded too: `domain` and `raw dim` against the entry, and the `bundled stats` column against the shipped `stats/<domain>_stats.json`, so a domain whose quantiles are added or removed cannot leave the column stale.
