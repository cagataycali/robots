### Fixed

- **examples/libero**: a rollout that recorded no frames is now refused on both `run.py` subcommands rather than only `isaac`. The shared eval-and-report loop prints a `videos=<path>` for whichever backend ran, but the zero-frame check was an optional per-backend hook that `_setup_mujoco` did not supply, so a blank MuJoCo rollout shipped a `success_rate` line naming a file that never landed on disk - and `libero_backend_matrix.py`, which parses those lines, recorded it as a completed cell. Measured with a real recording on a host that cannot create a GL context: `stop_cameras_recording` answers `status="success"` with `frames: 0`, and imageio drops the 0-frame mp4 rather than writing an empty file. The verdict now lives once in the shared loop and carries the recorder's own `render_refused` reason, which is where the remedy lives; `check_recording` keeps its remaining job of backend-specific recorder reporting and still runs first, so Isaac's `on_frame` retry counters precede the refusal.
