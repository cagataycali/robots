### Fixed: a `dds_security_config` credential that is not a string is refused instead of dropped from the participant QoS. `RosTelemetryBase._validate_dds_security_config` promised every required key was "a non-empty string" but graded `str(value).strip()`, and `str(None)` is the non-empty `"None"` - so `{'private_key': None}` (or `0`, or `False`) passed validation, and `HardwareRtpsBridge._build_security_qos`, which sets one `dds.sec.*` property per *truthy* credential, then set nothing for it: a `DomainParticipant` reached the wire with the DDS Security auth plugin loaded and no private key or governance. A truthy non-string was kept but stringified, so a `bytes` path arrived at cyclonedds as the literal `"b'file:/key.pem'"`. Each value is now graded itself, the refusal names the key and what arrived (`{'private_key': 'NoneType', 'governance': 'absent'}`), and a supplied `permissions_ca` is held to the same domain - so every credential the validator accepts is one the QoS carries verbatim, and nothing is created before the refusal.
