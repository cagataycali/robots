### Added: the robot catalog publishes the driver coverage join, generated at build

`list_driver_coverage()` is the only complete answer to "can this robot be
driven for real" - the lerobot robot types the registry declares joined with the
native drivers this package registers, including the group a single registry
cannot report because it is defined by two absences - and no page published it,
so a reader had to run Python to see it.

`docs/robots/index.md` now carries it under **Drivable for real**: one row per
registered robot with its lerobot type, its native driver class and its sim
asset, plus a per-category summary (75 robots: 16 through lerobot, 26 through a
native driver, 40 simulation-only). The table is generated by the new
`docs/hooks/coverage_matrix.py` from `strands_robots/registry/robots.json` and
the `_SHIPPED_DRIVERS` table, read with `ast` and `json` rather than by importing
the package, so the hook runs in the docs environment; a driver registered
tomorrow appears at the next build. `tests/test_docs_coverage_matrix_hook.py`
compares every published row against the live `list_driver_coverage()`,
`list_native_drivers()` and the registry, so the two readings cannot drift.

The hand-maintained "Counts at a glance" table is gone: the generated summary
states the same per-category counts, derived from the registry instead of typed.
