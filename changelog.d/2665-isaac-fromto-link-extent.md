### Fixed: an MJCF `fromto` link's extent now comes from its endpoints, not the size default

MJCF spells a capsule or cylinder two ways: `pos` plus `size="radius half-length"` along the geom's local z, or `fromto` plus `size="radius"` with the endpoints carrying both the placement and the axis extent. The MJCF-to-`ProceduralRobot` link reader behind `load_mjcf` read only the first, so a `fromto` link's single `size` component fell to the radius-only branch and its half-length was padded to the module's 0.05 m default however long the segment was. A three-link arm whose endpoints span 0.40, 0.28 and 0.50 m was published with 0.05 m links - 4.0x, 2.8x and 5.0x too short - with nothing raised and nothing logged.

The scene-object side of the same module already consulted the endpoints for exactly this reason, and the MuJoCo backend states the same rule in `scene_ops.fromto_fixed_size_components`. Both `fromto` consumers now share one segment-length helper, which keeps the existing expression bit-for-bit so scene-object bounds are unchanged (verified over 8000 random segments). `fromto` on a box or ellipsoid keeps its existing reading: that case needs a rotated-box bound this module deliberately does not compute.
