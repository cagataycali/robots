### Fixed

- **tools/episode_judge**: `sample_frames` now reads a one-component `observation.state` as the vector its metadata declares, instead of raising on it. LeRobot stores a feature of shape `[1]` unwrapped, so a single-DOF recording's parquet column holds a bare scalar float where a wider state holds a list, while `meta/info.json` declares `shape [1]` and one joint name either way. The reader iterated that value, so such a recording raised `TypeError: 'float' object is not iterable` - out through the `@tool` boundary, because `TypeError` is not among the exceptions the tool converts into an error envelope, and the module docstring promises that every tool returns the envelope and never raises. There was nothing to report either: the recording is healthy, and a single-DOF scene is ordinary (a gripper, a linear stage, a pan unit). The two tools had also disagreed on the same dataset - `load_episode` reported one `state_names` entry off the metadata while `sample_frames` raised on the column that metadata describes. The break landed before `include_images` was consulted, so the whole multimodal decode path was unreachable for such a dataset; it now returns one block per camera per sampled position as documented. A state of two or more components is unchanged, and an absent state column still reports no state.
