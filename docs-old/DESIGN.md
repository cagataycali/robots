# strands-robots docs, from scratch

Date: 2026-09-27. Branch `docs/from-scratch-20260927` in worktree `~/robots-docs`.
Owner decision: rewrite the docs site from zero. Nothing is pushed until the owner says so.

## 1. Thesis

The old site (115 pages, 25 MB of assets, hand-written catalog tables, a reference tree
that mirrors the module tree) documents the code. The new site documents the product.
A visitor must be able to answer three questions inside thirty seconds without scrolling:

1. What is this? One `Robot` object, any robot, sim or real, driven by an agent.
2. Does it work? A live robot in the browser they can move with a finger.
3. How do I start? One install line, four lines of Python.

Everything else is one click deep, organised by what the reader is trying to do
(start, pick a robot, learn a workflow, look something up), never by where the code lives.

The stobor site (cagataycali.github.io/stobor) is the floor: paper/dark palette, one accent,
Inter + JetBrains Mono, generated tables, short pages. This site goes above it with the
3D viewer, a real landing page, per-robot pages, and a reference generated from the source.

## 3. The viewer (the centerpiece)

`<robot-viewer name="so101"></robot-viewer>` anywhere in a page. Vanilla ESM web component,
no bundler. Dependencies via import map on jsDelivr, all pinned:

- `@mujoco/mujoco@3.14.0` (official DeepMind WASM bindings, 10 MB wasm, single-thread build,
  no COOP/COEP headers needed on GitHub Pages)
- `three@0.170.0` + `OrbitControls` (touch: one finger orbit, two fingers pan/zoom)

Robot assets are NOT committed. They stream from jsDelivr at view time:

- menagerie robots: `https://cdn.jsdelivr.net/gh/google-deepmind/mujoco_menagerie@c96a32d28fb5da84da38c1da4d749e7a13212855/<asset.dir>/`
- github-source robots: `https://cdn.jsdelivr.net/gh/<repo>@<ref>/<subdir>/`

Proven 2026-09-27 in node: SO-101 scene.xml + so101.xml + 18 STL (17.4 MB) into `MjVFS`
via `addBuffer`, `MjModel.from_xml_string(xml, vfs)`, `mj_forward`, named joints with
ranges, 50 steps: ~7 s cold. So:

- Never autoload on a page with many robots. The catalog shows the static
  `sim_render_<name>.png` thumbnail; the per-robot page shows a poster with a
  "Load 3D (17 MB)" button; the landing hero autoloads exactly one robot (so101) when
  the element is in view, with a progress bar that counts bytes.
- Loading: parse the scene xml for `<include file>`, parse each included xml for
  `meshdir`/`texturedir` and every `file="..."` on `<mesh>`/`<texture>`/`<hfield>`; fetch
  all in parallel; report progress; unknown geom types fall back to a bounding box.
- Rendering: one `THREE.Mesh` per mjGEOM_MESH built from `mesh_vert/mesh_face/mesh_normal`
  (indexed BufferGeometry, cached by mesh id); primitives via three geometries; colour from
  `geom_rgba`, or `mat_rgba` when `geom_matid >= 0`; group 3+ geoms (collision) hidden by
  default, toggle in the chrome. z-up camera, soft key light + hemisphere, ground grid.
- Interaction: joint sliders generated from `njnt` (hinge/slide only, name + range);
  moving a slider writes `qpos[jnt_qposadr]`, calls `mj_forward`, re-reads `geom_xpos/xmat`.
  A "Physics" toggle steps `mj_step` at real time with `ctrl` tracking the sliders when
  `nu > 0`. A code panel mirrors the sliders as `robot.act({...})` with the live values.
  Reset, collision toggle, fullscreen. Keyboard: arrows orbit, R reset.
- Memory: `.delete()` every embind handle on unload; `disconnectedCallback` disposes three.
- Failure: every error is a sentence in the viewer chrome ("cdn.jsdelivr.net unreachable",
  "scene_left.xml has no meshes we can render"), never a blank canvas.

The manifest (`assets/viewer/robots.json`) is generated at build from the registry with
`name, description, category, joints, aliases, base_url, scene, sim, real, thumbnail`.
A robot without an `asset` block gets `sim: false` and no viewer.

## 4. Information architecture rules

- Nav has six tabs: Start · Robots · Learn · Reference · Project · GitHub. No page is more
  than two clicks from the landing page.
- Pages answer one question each and stay under 900 words (the repo's word-budget grader
  is the ratchet; we do not exempt new pages).
- Every old URL gets a redirect (`docs-old/mkdocs.old.yml` lists 115 pages; the new
  `redirect_maps` covers all of them plus the old `redirect_maps` targets).
- Generated over hand-written wherever the source can answer: the catalog, per-robot pages,
  the coverage matrix, the tool reference, env vars, refusal codes, API reference. A hook
  reads files (robots.json, source text) and never imports the package.
- Every code fence that claims to run must run against `strands_robots` at this commit.
  Lanes verify fences with `~/robots/.venv/bin/python` (the full install) before landing.
- Numbers (robot count, provider count, LOC) come from the numbers hook, never typed.

## 5. Voice

- Short declarative sentences. Present tense. Second person for instructions.
- No em dashes, no en dashes. Use commas, colons, or a new sentence.
- No "simply", "just", "easily", "powerful", "seamless", "robust", "leverage".
- No promises: a feature is documented when its code path exists at this commit.
  If a thing is partial, say exactly what works and what does not.
- Headings are nouns or imperatives ("Install", "Move a joint"), not questions.
- The first paragraph of every page says what the reader will have at the end of it.
- Code first, prose second. A page may open with a fence.

## 6. Visual

- Palette from stobor: paper `#faf8f3` / ink `#1b1b1b` / accent `#ff6a00`; dark `#111`.
  Material `primary: custom`, `accent: custom`, Inter + JetBrains Mono.
- Landing: full-bleed hero, headline (max 8 words), one sentence, install line, live
  viewer on the right (poster on mobile), three proof numbers under it, then six cards
  (Start, Robots, Agents, Simulation, Hardware, Mesh), then a "one API, sim or real" side
  by side fence, then footer. `hide: [navigation, toc]`.
- Cards: 1 px border, 12 px radius, hover lifts 2 px, accent on the title only.
- Robot cards: thumbnail 4:3, name, family chip, joints, sim/real badges, aliases muted.
- No stock photography, no gradients over text, no emoji in headings.

## 8. Definition of done (coordinator runs before telling the owner)

1. `.venv-docs/bin/mkdocs build --strict` passes with zero warnings.
2. Every page in `docs/` is in the nav or explicitly `not_in_nav`.
3. Every old path from `docs-old/mkdocs.old.yml` resolves through a redirect.
4. `python3 docs/hooks/check_fences.py` runs every `python` fence marked runnable and reports green.
5. The viewer loads so101, g1, spot, leap_hand, and microduck in Chrome and Safari on this Mac
   (screenshots in `docs-old/handoffs/viewer-proof/`), each with sliders moving the robot.
6. No page over 900 words (`python3 docs/hooks/word_budget.py`).
7. `rg -n "—|–" docs/` returns nothing.
