## Open questions and gotchas

1. **`~/robots/.venv` has lerobot 0.5.1; the package requires `lerobot>=0.6.1`.** `sim.start_recording` fails there with `No module named 'lerobot.utils.feature_utils'`, so every recording fence on `data/record.md` and `data/stream-and-sync.md` is `sketch`. If the coordinator upgrades that venv (`uv pip install 'lerobot[feetech,dataset]>=0.6.1,<0.7.0'`), the record.md opening fence is written to run as-is and should be promoted to a runnable `python` fence and checked.
2. **Mesh fences reach every process on this host.** The local Zenoh router at `tcp/127.0.0.1:7447` means a fence that starts a mesh sees (and can command) any other mesh process on the machine, including a running `strands-robots dashboard`. While probing I ran `emergency_stop()` once with multicast on; it reached the owner's live dashboard on :8090 (pid 75253) and its spawned `so101-arm-1` sim peer, which engaged their lockouts. The dashboard's own `/api/safety` still reports `unknown`. That process was started by the owner at 17:50 for dashboard verification; I did not restart it. The shipped `safety-and-estop.md` page has no runnable fence for exactly this reason and says so.
3. `strands_robots/drivers/unitree/_common.py` has `UNITREE_SDK_DOCS = "docs/reference/hardware/unitree-g1.md (Installing the Unitree SDK)"`, printed in the missing-SDK refusal. The new page is `docs/learn/hardware/unitree.md` (section "Install the SDK"). The redirect covers the URL; the string in the source is a follow-up for the PR that lands the site (lane rules forbid editing `strands_robots/`).
4. The task brief asked for a `dry_run/confirm` posture section on agents.md. No robot tool has a `dry_run` flag at this commit (only `mesh.iot.bootstrap` does); the page says so and documents `mode="sim"` as the dry run, plus the dashboard's `STRANDS_DASH_TASK_REQUIRES_CONFIRM`.
5. Mesh topics are not declared in one place (keys are literals in `mesh/core.py`, `mesh/sensors.py`, `mesh/input.py`), so `topics.md` is a hand table checked against those files, as the brief allowed. A generator would need the source to move the keys into one constant table first.
6. `learn/hardware/drivers.md` word count (676) excludes the generated table (~250 words at build). The budget grader should measure the source file, as `word_budget.py` presumably does.
7. `pose_tool`'s refusal text on agents.md is quoted verbatim from a live run; if `_command_gate._no_operator_remedy` wording changes, that block and the fence output drift together and `check_fences` still passes (it checks exit status, not output). A grader that diffs fence output against the page would catch it.
