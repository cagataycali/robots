## Facts worth knowing (verified against the source)

- `Robot("so101")` returns `MuJoCoSimEngine`, tool name `so101_sim`; SO-101 joints are
  named `1`..`6` (labels in `get_robot_state()["content"][1]["json"]["joint_labels"]`).
  `send_action({"shoulder_pan": ...})` on the sim is refused by name.
- `Robot("so101", mode="real", driver="strands", transport="twin")` builds the real
  `FeetechDriver` over the model, no hardware, degrees in and out. Best rehearsal path.
- The lerobot-driver `Robot` tool gates `execute`/`start` through `gate_motion`
  (`STRANDS_ROBOT_COMMAND_ALLOW`, `BYPASS_TOOL_CONSENT`, interrupt id
  `robot-command-approval`). The native drivers' `move_to` action is NOT gated at
  `1d12a659`; both pages say so. D4 (learn/agents, hardware/drivers) should say the same.
- `download_assets(action="status")` reports every robot; `robots=` narrows only a download.
- lerobot calibration is looked up by the hardware Robot's `id`, which defaults to the tool
  name (`so101`), so the calibrate command on the page uses `--robot.id=so101`.
- `FeetechDriver.cleanup()` leaves torque as it is; `stop()` (async) releases it.
