## Decisions

1. **Shape: family pages + per-robot pages, both committed.** An H2 per robot on a family page would put 23 arms with hardware tables on one page and break the 900-word budget, so family pages are the card grid plus a text table, and every robot has its own page for deep links (`robots/so101/`). Files are written into `docs/robots/` at `on_pre_build` rather than injected through `on_files` so the nav can name them, graders can grep them and a registry change shows as a reviewable diff. Regeneration is idempotent.
2. **`real` = the coverage join, not `bool(hardware)`.** The manifest's `real` (24) misses `panda`, `fr3`, `fr3_v2`, `ur5e`, `ur10e`, `open_duck_mini`, which have a native driver and no `hardware` block. The pages and cards use `coverage.row(name).real` (drivers reachable: 29 robots, 20 native + 16 lerobot with overlap). Coordinator: consider the same join for `manifest.py`'s `real`.
3. **Hardware facts live in one table in the hook** (`DRIVERS`, keyed by driver class, `module` names the source file). Every line was read from that module at `1d12a659`: constructor kwargs and defaults, the SDK install line the driver's own refusal names, the checks `connect_eagerly`/`send_action` perform. Nothing was copied from `docs-old`; the old so-arms/unitree/ur pages were used only to know what to look for.
4. **Policies line.** No source table maps robots to providers, so the line says: pick from the policy matrix; then names the providers whose own module binds them to this body (`wbc`, `wbc_gait`, `kimodo`, `protomotions` for `unitree_g1`; `microduck` for `microduck`), each witnessed by a literal. Everything else says "no provider is bound to this body".
5. **Default driver spelled out.** The real fence pins `driver="strands"` only when the registry does not already declare it (`resolve_driver` precedence), and pins `driver="lerobot"` only for `unitree_g1`, where the registry default is `strands`.
